and the loaded KEYBOARD module's exact TNDYK3.DRV basename. It reads the

DLL COMPONENT VERIFICATION
The exact final DLL passes 28 native cases and 17 accepted one-shot requests;
a duplicate take is rejected each time. Independent host checks pass 238 Hold
callbacks/19 post attempts plus the original 30-callback idle regressions.
They cover chain results, negative/no-remove codes, modifier and mouse
interruptions, stale input, owner/foreground/token lifetime, dialog/capture/
saver exclusions, failed posting/unhooks, partial removal and nested teardown.

HC_NOREMOVE is always chained unchanged. Win3 can otherwise suppress a later
HC_ACTION release and strand gesture ownership. All ownership and consumption
occur only on HC_ACTION. A downstream hook that discards a key cancels our
action while preserving the owned release. Removal stays latched through its
private-message drain; WEP does not pump messages. Old idle exports 1-6 remain
compatible and the new API appends 7-12. Idle and Hold own separate hooks and
library references.

Independent source-extracted shell tests pass 18 fault groups plus 18 final

BUILD AND LIMITS
MSC6 uses /G0 /Gw /AS for the shell and /G0 /Gsw /ASw for the DLL, with
period MASM/LINK and Win 3.0 imports. Fresh shell rebuild is byte-identical.
Shell code is 61,058 bytes; its scoped audit checks 22,368 instructions.
The DLL audit checks 1,772 instructions from entry and exported API roots.
Both audits find no post8088 suspects.
DLL code/data are fixed, preloaded, nondiscardable and shared as required;
there is no DLL local heap or CRT. Scoped disassembly audits and exact native
8086 execution supplement compiler flags; imported Windows code, unresolved
indirect branches and untraced far calls are outside disassembly scope.

Native GUI host fixtures use real Windows 3.0 WIN/R with 8086_prefetch and 640KB,
but DOSBox host-mounted DOS. Genuine cases separately boot actual DOS 6.22
images under 8086 emulation. No user CF is accessed and no OS/toolchain binary
is distributed. Program Manager itself rewrites/normalizes group files when
explicitly launched; those bytes match a separate Program Manager control.
TSHELL does not modify the group definitions.

PM_NOREMOVE readers can inspect Hold; GetKeyState(VK_SCROLL) polling still
observes its toggle. Removed/dispatched owned Scroll messages are suppressed.
No keyboard-state rewriting is used. Arbitrary custom modal loops, every
possible programmatic activation race and native third-party hook failures
are not exhaustively covered. Retention after a failed detach is a deliberate
lifetime safeguard, not a claim that abnormal termination cannot fail.

Screenshots are actual final 04 emulated Windows output, not reconstructed UI.
Physical Windows Hold behavior, physical timing and audio remain unverified.
