Machine (86box.cfg, written by src/xtpan/PCP86.PY prepare --target xtpan|xtbase):
  machine = tandy1000hx        Tandy 1000 HX. 86Box has no Tandy 1000 EX; the HX
                               is the EX's sibling (same 8088 at 7.16 MHz, same
                               video gate array, video RAM in system RAM; the HX
                               adds DOS in ROM and a different case).
  cpu_family = 8088, cpu_speed = 7159092, cpu_multi = 1, cpu_use_dynarec = 0
                               86Box's cycle-counted 8088 interpreter at the EX/HX
                               clock. This is not a DOSBox "cycles" setting; still,
                               it is an emulation, and real 8088 timing (wait
                               states, DRAM refresh, video contention) may differ.
  mem_size = 640, time_sync = disabled
  gfxcard = internal           the HX's own Tandy video
  hdc_1 = xtide (XT BIOS)      PC DOS 3.20 + Windows 3.0 disk image (raw sha256
                               f55fe24b...117561, src/pcjr/PCJSIMG.PY on the PCjr
                               line), private
  serial1 = serial passthrough to a host pty, driven byte-exactly by PCPMOUSE.PY
                               (Microsoft serial mouse protocol, 1200 baud)
  keyboard: the HX's own; keys sent with xdotool

Guest changes (PREP.JSN of each run): display.drv = XTPAN.DRV or TR53216.DRV
(the shipped Windows XT driver); CONFIG.SYS FILES/BUFFERS only; [keyboard]
type=1; WIN.INI MouseSpeed=0, Wallpaper=BARS16.BMP, load=C:\XTPAN\XTPAN.EXE,
[XTPan] LogFile=C:\XTPAN\XTPAN.LOG (and Enabled=0 for the helper-off run);
AUTOEXEC runs RESERVE.COM (the shipped helper) before the DOS prompt.

Timing: all times are measured inside the emulated machine with Windows'
GetCurrentTime (BIOS tick, 55 ms resolution), summed over many operations.
They describe 86Box's emulated HX, not a real EX/HX.

Every guest run held the shared emulator lock (src/xtpan/EMULOCK.PY): a
non-blocking flock refused when busy, no other emulator process running,
a time bound, release in finally; each run's LOCK.JSN is kept with it.
