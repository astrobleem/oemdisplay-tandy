# One Panning application: native acceptance

Consumers run PAN or PAN /SETTINGS. A transient dispatcher detects the installed
display and starts one backend owner. Shared settings and bounded queued keys run
inside that owner; other backends stay on disk. There is no resident broker.

The former PCjr and ColorPlus desktops were 320x400 behind a 320x200 view: their
equal widths left no horizontal pixels. Both now expose 640x400 through the same
320x200 physical screen, using software viewport copies. HPXY retains its working
hardware/software choice. Ordinary fixed displays use the window workspace.

All final runs read the seven actual installed helper files from their stopped
fixtures and match the exact qualified bytes. Native canonical FRESH and UPDATE
prepare 387 and 99 verified files respectively. Standalone root SETUP installs
all helpers, upgrades only the exact preceding PCjr/ColorPlus driver, and preserves
unrelated startup entries/settings. Every final owned emulator is stopped and
its byte lease released; failed or blocked diagnostic records remain identified.

Each new driver also passed an independent native raster run: 704,000 pixels
across eleven captured frames, zero mismatches, including split-band operations,
8bpp DIB palette handling, edges, cursor restore and sixteen pans without a free
memory change. Existing HPXY, CGA and ordinary driver/grabber bytes are preserved;
their preceding driver qualification is reused. These are emulator and native API
checks, not physical hardware or physical-mouse qualification.

Both new software desktops require 128,000 shadow bytes, 64,000 more than their
preceding vertical profile; the physical video page remains 32KB. Normal 640KB
real-mode fixtures use neither EMS nor XMS. Driver file growth is 1,520 bytes on
PCjr and 1,952 on ColorPlus. The selected XY owner grows 286 file bytes (288
declared NE segment bytes); its heap and stack are unchanged. The shared key DLL
is unchanged at 2,085 bytes. All seven installed helpers total 130,520 disk bytes.
PCjr free memory was 170,016 bytes with observer and active owner; closing the
owner freed 43,712 bytes. Other measured samples and precise limits are in
[COST.JSN](COST.JSN); these include fixture observers and existing shell helpers.

[FINAL.JSN](FINAL.JSN) binds source, native binaries, installed observations,
installer transactions, raster receipts, screenshots and all five closed package
inventories. [EVIDENCE.ZIP](EVIDENCE.ZIP) retains raw API states, scan-code timings,
valid video dumps, build/lease receipts and setup logs, without OS images, ROMs
or toolchains. PCJR-SET.PNG decodes the native PCjr SETTINGS.BIN; CGA-SET.PNG
decodes native CGA100 REOPEN.BIN through tools/PAN/SHOT.PY. Other screenshots
are native emulator captures. Cropped FRAME API diagnostic captures are not used
to establish dialog fit. Incorrect-segment CGAPAN BIN dumps are excluded; that
run's independent API/installation/input/exit evidence remains valid.
