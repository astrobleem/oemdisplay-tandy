WHAT CHANGED
BORDER7 preserves the original TRIAL6 Output eligibility gate and renderer. One or two validated
scanline intervals refresh their outward-rounded logical byte columns separately, without
reconverting the gap. Thin two-point lines refresh a conservative endpoint bounding rectangle.
Longer/unproven inputs retain the proven row or full-frame fallback. The single full-width span
keeps the old row path. ROPs are executed once by the unchanged renderer; refresh only copies
the final shadow.
TEXT7 first requires the existing proven raster-font row bounds. It adds a fail-closed
short-label path for 1..64 characters with no explicit width vector or spacing. The pinned font
header, glyph widths and default-glyph substitution must fit a conservative maximum-width bound.
Explicit opaque fill is included. Unknown, transformed, decorated or otherwise unsupported cases
retain the old row/full fallback. Eligible text rows and columns use the already-qualified
retained-cursor helpers, avoiding hide/redraw when the cursor is elsewhere.
The new code has no persistent buffer or global-state allocation. Output adds 10 private local
stack bytes; each text wrapper adds 4 private local bytes plus temporary
saved-register/span-validation stack use. Final drivers grow by 864..960 bytes over TRIAL6.
Rasterizers, cursor assembly, DIB bridge, conversion helpers, identity/full-shadow
resynchronization and package/release pins remain unchanged.
Monochrome policy: the initial split scanline path measured 6.866 ms against 6.418 ms for TR6.
The final 640x200x2 build keeps the original scanline row copy and reproduces 6.418 ms, while
retaining narrow thin-line updates. Superseded candidate measurements are excluded from the
final table.
The 1-pixel Rectangle workload remains on its conservative full fallback and is not materially
accelerated. This trial does not claim every border or every string is optimized.

LIMITS
Physical Tandy EX/HX behavior and timing, genuine DOS variants, CF reliability, power-loss
recovery, every font/ROP/application and arbitrary invalid caller memory are not established by
these tests. In particular, the existing 640x200x4 DOSBox-X model qualification remains:
emulation does not by itself prove original EX/HX mode 0Ah behavior. That mode is four colors
(black/red/green/white), never 640x200x16. No EMS/XMS/UMB shortcut or logical-plane increase
changes the physical color depth. Caller buffers still must be valid live stable allocations;
range/alias checks are not an allocation-ownership proof.
