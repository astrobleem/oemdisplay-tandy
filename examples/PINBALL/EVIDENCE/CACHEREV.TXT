Fixes verified
- A failed bitmap SelectObject now destroys the unused DC and bitmap,
  clears the cache handles, and reaches direct-render fallback.
- A failed initial cache PatBlt now releases the cache and falls back.
- A failed restore BitBlt now clears/redraws the dirty area directly.
  Previously these paths could retain an unusable cache or stale pixels.

Lifecycle and Win16 checks
- CompatibleBitmap is created from the window DC, not the new memory DC;
  this avoids inheriting the memory DC's default monochrome surface.
- The old bitmap is restored before deleting the DC and owned bitmap.
  Stock pens, brush and font are never deleted. Normal repeated paints
  reuse one cache; WM_SIZE and WM_DESTROY release it. Failed DC/bitmap
  allocations leave no owned cache active. Stale oldbits is unreachable
  when board is zero, and is replaced before the next successful cache.
- APIs used are declared by the repository Win16 WINDOWS.H. No Win32-only
  handles, pointer-width assumptions, DIB sections, or new large buffers
  were introduced. Native compilation/execution is separate evidence.

Dirty rectangles and clipping
- Each 11x11 ball dirty rect contains its old/new 5x5 rendered square.
- The flipper update rectangle contains all endpoints and both parallel
  lines for angles 0..4. Score invalidation includes the measured 8/10px
  fonts and previously considered 14px font, starting at y1.
- Launch, drain, reset, pause and focus loss use full-client invalidation.
  Overlay text is redrawn when its vertical region intersects the update.
- Cache and destination share client coordinates. BeginPaint clips output
  to the actual update region; its rcPaint bounding box stays inside the
  client-sized source bitmap. Fallback table drawing is similarly clipped.
  WM_SIZE invalidates the whole client after discarding the old-size cache.
- No normal-path stale-pixel or out-of-range blit defect was identified.
