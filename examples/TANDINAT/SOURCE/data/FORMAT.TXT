TANDI01 DISK FORMAT, VERSION 1
============================
All multibyte numbers are unsigned little-endian. The file starts with this
64-byte header. No compiler structure layout or native alignment is used.

Offset  Bytes  Meaning
0       8      Magic: 54 41 4E 44 49 30 31 00 (TANDI01 plus NUL)
8       2      Version, exactly 1
10      2      Number of characters, 1..2000
12      2      Number of questions, 1..256
14      2      Row bytes: ceil(number of questions * 3 / 8)
16      2      Column bytes: ceil(number of characters * 3 / 8)
18      2      Reserved, zero
20      4      Question offset-table location, exactly 64
24      4      Character-name offset-table location
28      4      Character-major row-matrix location
32      4      Question-major column-matrix location
36      4      String-pool location
40      4      Entire file size in bytes
44      4      Sum of bytes at offsets 64 through EOF, modulo 2^32
48      16     Reserved, all zero

SECTIONS, CONTIGUOUS IN EXACT ORDER
----------------------------------
QTable:  question_count uint32 absolute string offsets.
NTable:  character_count uint32 absolute string offsets.
Rows:    character_count packed records of row_bytes bytes.
Columns: question_count packed records of column_bytes bytes.
Strings: all question strings in question order, then names in character
         order, each NUL terminated and without alignment or trailing data.

Canonical offsets:
  qoffset = 64
  nameoffset = qoffset + 4 * question_count
  rowoffset = nameoffset + 4 * character_count
  coloffset = rowoffset + character_count * row_bytes
  stringsoffset = coloffset + question_count * col_bytes

Questions are nonempty printable ASCII (0x20..0x7E), at most 79 bytes before
NUL. Names use the same character range, at most 39 bytes before NUL.
Each table entry points to the next string, not an alias or substring.

PACKING
-------
Answer values: NO=0, PROBABLY_NO=1, UNKNOWN=2, PROBABLY_YES=3, YES=4.
Values 5, 6 and 7 are invalid. For answer index i, its first bit is 3*i.
The low bit goes into the lowest available bit position of that byte; the
remaining bits continue toward higher bits and then the next byte. Each
record begins at its own byte boundary. Unused high bits in the record's
last byte must be zero. Example [0,1,2,3,4] packs as hex 88 46.

Rows allow efficient access to every answer for one character. Columns
allow efficient access to one question's answers for every candidate.
They encode exactly the same matrix; the compiler and validator compare
all corresponding values. An 8088 reader need not keep the whole database
resident. At maximum capacity one row is 96 bytes and one column 750 bytes.

VALIDATION
----------
DBBUILD.PY checks header magic/version/counts/reserved bytes, exact section
offsets and contiguity, file length, checksum, every string pointer and
terminator, printable ASCII, length limits, all packed values, unused bits,
and equality of the two matrix orientations. It rejects trailing bytes.
It validates generated bytes, writes through a temporary file, validates
the written bytes, then replaces the destination.

The required additive checksum detects common damage, not malicious changes.
It is NOT cryptographic authentication. Release evidence also records SHA-256.
Host checks are intentionally stricter than merely staying within offsets.
